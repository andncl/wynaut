# Report (step 5)

Two views of the campaign are built from here.

**The run tracker** (`python -m tools.timeline` → `build/tracker/runs.html`): one
square per run, coloured by its processing status or by the logged sensor
value, with milestones beside the timeline. Its hand-written inputs live here:

| Path | What | Who |
|---|---|---|
| `milestones.yaml` | events shown beside the timeline: `date` and `text` | anyone, or an agent on request |
| `run_marks.yaml` | runs marked by hand as `paper`, `failed` or `not_relevant`, with a `note` | the researchers, or an agent on request |

**The report** (planned; `tools/build_report.py` is still a placeholder): a
Slidev deck with one chapter per question in [PLAN.md](../PLAN.md), with
progress, figures, results and outcome. Researchers don't edit anything for it
here: their content comes from `PLAN.md` (text) and `figures/` (code).

| Path | What | Who |
|---|---|---|
| `slides.md` | generated by `python tools/build_report.py`, gitignored | nobody edits it |
| `pages/` | optional hand-written slides, e.g. an introduction; no results numbers | maintainer |
| theme, `package.json` | Slidev setup and layout | maintainer |

Build (needs Node, maintainer only):

```bash
python tools/build_report.py
cd report && npx slidev build      # HTML in report/dist/
npx slidev export                  # PDF
```

Hosting is optional: publish `report/dist/` and `build/tracker/` with GitHub or
GitLab Pages from CI, so everyone reads the same, current state in the browser.
The report needs the analysis outputs on the shared drive, so that job runs on
a machine that can reach it.
